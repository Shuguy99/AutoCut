# AutoCut — лента RuTube и плейлисты

Дата: 2026-10-20
Статус: на ревью

## 1. Цель

Добавить в веб-интерфейс два сценария:

1. **Лента популярных видео RuTube** — сетка карточек с превью, названием, каналом, длительностью и просмотрами. Кнопка на карточке подставляет ссылку в форму, чтобы сразу запустить нарезку.
2. **Плейлисты** — вставка ссылки на плейлист, список видео с чекбоксами, запуск нарезки для выбранных. Каждое видео обрабатывается отдельной задачей со своим прогрессом, папкой и отменой.

CLI получает паритет: `autocut run <url> --playlist-limit N` обрабатывает первые N видео плейлиста.

## 2. Не цели

- лента YouTube (с текущей машины недоступна; при появлении прокси — отдельная задача);
- «выбрать все» и массовые операции в списке плейлиста;
- сохранённые плейлисты, история, избранное, авторизация;
- фоновая синхронизация ленты и push-уведомления;
- параллельная обработка видео (worker остаётся один);
- докачивание длительности для flat-записей, где её нет.

## 3. Пользовательские сценарии

**Лента**

1. Пользователь открывает веб-интерфейс.
2. Над формой видит сетку «Лента RuTube»: превью, название, канал, длительность, просмотры.
3. Нажимает «В форму» — ссылка попадает в поле источника, страница прокручивается к форме, поле подсвечивается.
4. Проверяет настройки и запускает нарезку обычной кнопкой.

**Плейлист**

1. Пользователь переключает режим формы на «Плейлист» и вставляет ссылку.
2. Нажимает «Показать список» → видит превью, названия и длительности видео с чекбоксами.
3. Отмечает нужные, нажимает «Запустить выбранные (N)».
4. Получает N отдельных карточек задач: у каждой свой этап, прогресс, папка результата и кнопка отмены.

**CLI**

```bash
autocut run "https://rutube.ru/plst/308547/" --playlist-limit 5 --clips 3
```

Обрабатывает первые 5 видео последовательно, у каждого своя папка результата. Без флага поведение прежнее: скачивается первое видео.

## 4. Архитектура

```
autocut/
  feed.py            # NEW: RuTube recommendation API → карточки ленты
  downloader.py      # + list_playlist(), NotAPlaylistError
  jobs.py            # + submit_many(), лимит очереди параметром
  web/app.py         # + /api/feed, /api/playlist, /api/jobs/batch
  web/static/        # + блок ленты, режим «Плейлист», список с чекбоксами
  cli.py             # + --playlist-limit
```

Потоки данных:

```
лента:    браузер → GET /api/feed → feed.fetch_feed → RuTube API → карточки
плейлист: браузер → POST /api/playlist → downloader.list_playlist → yt-dlp flat
          → чекбоксы → POST /api/jobs/batch → JobManager.submit_many → N job'ов
```

`feed.py` не знает про FastAPI и yt-dlp; `downloader.py` не знает про HTTP-слой. Оба контракта тестируются отдельно.

## 5. Детали реализации

### 5.1 Лента RuTube

- Источник: `GET https://rutube.ru/api/v2/video/recommendation/main?limit=<n>&offset=<o>`, заголовок `User-Agent: Mozilla/5.0`. Авторизация не нужна.
- `fetch_feed(offset: int = 0, limit: int = 12) -> FeedPage` (`items: list[dict]`, `has_more: bool`, `next_offset: int`):
  - запрос через `urllib.request` (stdlib, без новой зависимости), таймаут 15 с;
  - **передискретизация:** у API запрашивается `raw = min(99, max(50, limit * 4))` записей, а наружу отдаётся до `limit` подходящих. Лента рекомендаций на ~90% состоит из длинных фильмов и аудиокниг; при фильтре 2–30 минут страница почти пустела (5–12 карточек на 99 сырых), поэтому одной страницей считаем сырую порцию, из которой набираем карточки;
  - отбрасываем записи с `is_deleted`, `is_livestream`, `is_on_air`;
  - оставляем только `120 <= duration <= 3600` секунд (до 1 часа: длиннее — тяжёлая транскрипция, короче — нечего нарезать);
  - маппинг: `id`, `title`, `channel = author.name`, `duration`, `views = hits or 0`, `thumbnail_url`, `url = video_url` (fallback `https://rutube.ru/video/<id>/`), `created_at = created_ts`;
  - страница сортируется по `views` по убыванию (лента рекомендаций уже ранжирована, но пользователю нужен «популярный» порядок);
  - дубликаты внутри страницы убираются по `id`;
  - `has_more = True`, если в сыром ответе было не меньше `raw` записей (фильтрация на это не влияет);
  - `next_offset = offset + raw` — сырой offset API для следующей страницы.
- Ошибки сети, HTTP ≠ 200 и невалидный JSON → `FeedError` с русским сообщением. Исключение не глотается.
- `GET /api/feed?offset=0&limit=12` → `{"items": [...], "next_offset": 50, "has_more": true}` (при `limit=12` сырая порция 50).
  - `limit` 1–24, `offset` ≥ 0;
  - `FeedError` → HTTP 502.
- `next_offset` берётся из `FeedPage.next_offset` (это сырой offset API, а не `offset + limit`); фронтенд дедуплицирует карточки по `id` между страницами.

### 5.2 Плейлисты

- `list_playlist(url, limit=30, proxy=None, cookies=None) -> PlaylistInfo`:
  - опции yt-dlp: `extract_flat="in_playlist"`, `noplaylist=False`, `playlistend=limit`, `skip_download=True`, `quiet`, `no_warnings`;
  - если `info["_type"] != "playlist"` → `NotAPlaylistError` (подкласс `DownloadError`);
  - записи без `id` или без http-ссылки пропускаются;
  - поля записи: `video_id`, `title`, `channel` (канал записи, иначе канал плейлиста, иначе `unknown`), `duration` (может быть `None`), `url`, `thumbnail`;
  - `PlaylistInfo`: `title`, `items`, `truncated` (`truncated=True`, если yt-dlp упёрся в `playlistend`);
  - `limit` 1–50, по умолчанию 30.
- Ссылки RuTube-плейлистов имеют вид `https://rutube.ru/plst/<id>/`; YouTube — `...&list=<id>`. Специальная обработка не нужна: yt-dlp сам определяет тип.
- `POST /api/playlist` body `{"url": "...", "limit": 30, "proxy": null}` → `{"title": "...", "items": [...], "truncated": false}`; прокси опционален, иначе берётся из конфига.
  - `NotAPlaylistError` или пустой список → HTTP 400 с текстом «это не плейлист или он пуст»;
  - `DownloadError` (сеть, приватный плейлист) → HTTP 502.

### 5.3 Пакетный запуск

- `JobManager.submit_many(sources: list[str], options: JobOptions) -> list[Job]`:
  - под одним lock проверяет, что все job'ы помещаются в очередь (`qsize() + len(sources) <= maxsize`);
  - если нет — `QueueFullError` с числом свободных мест, ничего не добавляя;
  - создаёт все `Job`, кладёт в `_jobs` и в очередь; при неожиданной ошибке откатывает добавленные записи.
- `JobManager(config, max_queue=3)` — default не меняется; веб-приложение создаёт менеджер с `max_queue=20`.
- `POST /api/jobs/batch` body `{"sources": ["..."], "options": {...}}`:
  - 1–20 источников, каждый непустой;
  - ответ `{"jobs": [...]}` в том же формате, что `POST /api/jobs`;
  - переполнение очереди → HTTP 429.
- Пакетные задачи не открывают SSE на каждую (браузер упрётся в лимит соединений); фронтенд использует общий polling раз в 3 секунды.

### 5.4 Веб-интерфейс

- Блок «Лента RuTube» над формой:
  - сетка карточек: превью 16:9 (`loading="lazy"`), название (2 строки), канал, длительность, просмотры;
  - просмотры форматируются: `1 234 567 → 1,2 млн`, `12 345 → 12,3 тыс.`;
  - кнопка «В форму»: `source.value = url`, `focus()`, плавная прокрутка к форме, подсветка поля на ~1,2 с;
  - кнопка «Показать ещё» догружает следующую страницу и скрывается, когда `has_more=false`;
  - состояния: загрузка (скелетоны), ошибка + «Повторить», пустая лента.
- Форма: сегментированный переключатель «Видео / Плейлист».
  - «Видео» — текущее поведение, кнопка «Сделать клипы»;
  - «Плейлист» — кнопка «Показать список»; настройки клипов/длин/формата применяются к каждому видео;
  - панель списка: чекбокс, превью, название, длительность (`—`, если неизвестна), счётчик выбранных; кнопка «Запустить выбранные (N)» неактивна при N=0;
  - после запуска панель очищается, задачи появляются в общем списке.
- Ошибки API показываются в существующем блоке `#form-error`; кнопки блокируются на время запроса.

### 5.5 CLI

- `run` получает `--playlist-limit N` (default 1, диапазон 1–50).
- Если `N == 1` — поведение не меняется (первое видео).
- Если `N > 1`:
  - `list_playlist(url, limit=N)`;
  - `NotAPlaylistError` → ошибка «это не плейлист» и код 1 (пользователь явно запросил плейлист);
  - для каждой записи последовательно вызывается `run_pipeline` с теми же опциями;
  - ошибка одного видео не останавливает остальные; в конце печатается сводка и код 1, если были ошибки.
- `--playlist-limit` действует только для URL; для локального файла игнорируется.

### 5.6 Ошибки

- `FeedError` — лента недоступна/пуста; HTTP 502, в UI кнопка «Повторить».
- `NotAPlaylistError` — ссылка не является плейлистом; HTTP 400.
- `DownloadError` — сеть/приватный плейлист; HTTP 502.
- `QueueFullError` — HTTP 429 с числом свободных мест.
- Все сообщения — по-русски; технические детали остаются в логах.

## 6. Тестирование

- `tests/test_feed.py`: маппинг и фильтрация (удалённые, стримы, короткие/длинные), сортировка по просмотрам, дедупликация, `FeedError` на битом JSON; эндпоинт 200 и 502 с замоканным `fetch_feed`.
- `tests/test_downloader.py`: `list_playlist` на фейковом `YoutubeDL` (поля, лимит, пропуск записей без ссылки), `NotAPlaylistError` для одиночного видео.
- `tests/test_jobs.py`: `submit_many` создаёт N задач, переполнение очереди не добавляет ни одной.
- `tests/test_api.py`: `/api/playlist` (успех, 400, 502), `/api/jobs/batch` (успех, 429, валидация).
- `tests/test_cli.py`: `--playlist-limit` вызывает пайплайн для каждой записи; ошибка одного видео не прерывает остальные.
- E2E вручную: реальный RuTube-плейлист `https://rutube.ru/plst/308547/`, запрос ленты, скриншот UI в браузере.

## 7. Риски

- Endpoint рекомендаций RuTube неофициальный и может измениться. Изоляция в `feed.py` + понятная ошибка + кнопка «Повторить»; при поломке лента просто не показывается, остальное приложение работает.
- «Рекомендуемое» — не редакционный чарт. Просмотры показываются, чтобы пользователь сам оценивал; сортировка внутри страницы по просмотрам.
- В flat-списке некоторых экстракторов нет длительности — показываем `—`, на запуск это не влияет.
- Пакет из 20 видео занимает единственный worker надолго. Отменить можно каждую задачу, включая стоящие в очереди.
- YouTube-плейлисты не проверяются E2E с этой машины (YouTube недоступен); логика общая, проверяется фейками.
