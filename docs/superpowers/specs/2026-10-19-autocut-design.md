# AutoCut — дизайн приложения

Дата: 2026-10-19
Статус: на ревью

## 1. Цель

Локальное приложение, которое по ссылке на YouTube (или локальному файлу) автоматически:

1. скачивает видео;
2. находит N самых «живых» фрагментов длиной 20–60 секунд;
3. делает вертикальные клипы 1080×1920 с вжжёнными субтитрами снизу;
4. раскладывает результат по папкам на каждое исходное видео.

Управление: локальный веб-интерфейс и CLI поверх одного движка.

## 2. Не цели (v1)

- публикация в TikTok и работа с аккаунтами;
- авто-рефрейминг по лицам (в v1 — размытый фон или центральный кроп);
- внешние LLM API;
- музыка, переходы, эффекты, обложки;
- многопользовательский режим и база данных;
- облачное хранилище.

## 3. Пользовательские сценарии

**CLI**

```bash
autocut run "https://www.youtube.com/watch?v=..." --clips 5 --min 20 --max 60 --format blur
autocut run ./video.mp4 --clips 3 --proxy socks5://127.0.0.1:1080
autocut trending --region RU --clips 5
autocut web --port 8000
```

**Web**

1. Пользователь вставляет ссылку или путь к файлу, задаёт число клипов, длину, формат кадра, прокси.
2. Видит прогресс по этапам: скачивание → анализ → субтитры → рендер.
3. Получает сетку готовых клипов с превью, оценкой, таймкодами и кнопкой скачивания.
4. Видит путь к папке результата.

## 4. Архитектура

```
autocut/
  __main__.py        # python -m autocut
  cli.py             # argparse, команды run/trending/web
  config.py          # defaults + config.yaml + env
  pipeline.py        # оркестрация одного job
  downloader.py      # yt-dlp, локальные файлы, прокси, trending
  media.py           # ffmpeg/ffprobe: аудио, сцены, длительность
  transcribe.py      # faster-whisper, кэш транскрипта
  scoring.py         # кандидаты, оценка, NMS, привязка к фразам
  subtitles.py       # группировка слов, ASS
  render.py          # вертикальный кадр, вжигание субтитров
  storage.py         # пути, slug, metadata, transcript.srt
  jobs.py            # in-memory очередь, статусы, прогресс
  web/
    app.py           # FastAPI: API + статика
    static/index.html
    static/app.js
    static/style.css
tests/
```

Поток данных:

```
источник → downloader → work/source.mp4
         → media (audio.wav, scenes) ─┐
         → transcribe (words, segments) ─┤
                                        ├→ scoring → N окон
                                        └→ subtitles (ASS на клип)
                                              → render (mp4 + jpg)
                                              → storage (папки, metadata.json)
```

Каждый модуль имеет один контракт и тестируется отдельно; `pipeline.py` не содержит ffmpeg- и yt-dlp-деталей.

## 5. Детали реализации

### 5.1 Загрузка

- yt-dlp как библиотека, формат `bv*[height<=1080]+ba/b`, слияние в mp4.
- `--no-playlist`, имя рабочего файла фиксированное (`source.mp4`), оригинальное название берётся из метаданных.
- Прокси: `http://`, `https://`, `socks5://`; передаётся в yt-dlp. Cookies — опциональный файл.
- `trending`: лента `https://www.youtube.com/feed/trending?gl=<REGION>` через yt-dlp (best-effort, требуется доступ к YouTube), берётся верхнее видео; при ошибке — понятное сообщение.
- Локальный файл: проверка существования, ffprobe, копирование/симлинк в рабочую папку.
- Ограничение: возрастные/приватные видео без cookies не поддерживаются (сообщение об ошибке).

### 5.2 Транскрипция

- faster-whisper, модель `small` (настраивается), `device=cpu`, `compute_type=int8`, `vad_filter=True`, `word_timestamps=True`, авто-определение языка.
- Кэш: `transcript.json` в папке job; повторный анализ того же видео не перезапускает модель.
- Если речи нет — клипы всё равно рендерятся, субтитры пустые.

### 5.3 Оценка фрагментов

- Аудио: RMS по окнам 0.5 с (ffmpeg → raw PCM → numpy), нормализация в процентили.
- Речь: доля окна, покрытая словами Whisper.
- Сцены: `select='gt(scene,0.35)'`, число смен на окно.
- Хуки: словари ru/en («почему», «секрет», «ошибка», «главное», «never», «secret»…), частота на 100 символов.
- Завершённость: близость границ окна к границе предложения (пунктуация + пауза > 0.6 с).
- Кандидаты: старт каждые 1 с, целевая длина 30 с (настраивается), затем границы сдвигаются к ближайшей границе фразы в пределах 20–60 с.
- Итог: `0.40*energy + 0.25*speech + 0.15*scenes + 0.10*hooks + 0.10*completeness`.
- NMS: выбрасываем кандидатов с пересечением > 30 %; берём top-N. Оценка сохраняется в metadata.

### 5.4 Субтитры

- Слова группируются в реплики: 3–5 слов, ≤ 42 символов в строке, ≤ 2 строки, длительность 0.8–4 с; разрыв по пунктуации и паузам.
- ASS: PlayRes 1080×1920, шрифт Liberation Sans (проверен в системе, поддерживает кириллицу; fallback sans-serif), размер 48, жирный, белый с чёрной обводкой 4 px и тенью, `MarginV=230` — выше интерфейса TikTok.
- Тайминги обрезаются по границам клипа и сдвигаются в 0.
- Спецсимволы `{}` экранируются.

### 5.5 Рендер

- `blur` (по умолчанию): фон — исходник scale+crop до 1080×1920 с `gblur=sigma=30`; поверх — исходник целиком по ширине 1080, по центру.
- `crop`: scale до заполнения 1080×1920 и центральный кроп.
- Вжигание ASS через фильтр `subtitles`, путь экранируется.
- Кодек: libx264, `preset veryfast`, CRF 20, `-movflags +faststart`, AAC 128 kbps 48 kHz; 30 fps.
- Превью: jpg из середины клипа.
- Если исходник короче минимальной длины — один клип на всё видео с предупреждением.

### 5.6 Структура результата

```
output/<channel-slug>/<video_id>_<title-slug>/
  source.json          # ссылка/путь, название, канал, длительность, параметры
  transcript.srt
  transcript.json
  metadata.json        # список клипов: таймкоды, score, файлы
  clips/
    clip_01_score-0.87.mp4
    clip_01.ass
    clip_01.jpg
```

- Slug: буквы/цифры (включая кириллицу), остальное → `-`, обрезка до 60 символов; `video_id` гарантирует уникальность.
- Существующая папка не перезаписывается: суффикс `_2`, `_3`.
- Рабочие файлы — в `work/<job_id>/`, удаляются после успеха (настраивается).

### 5.7 Web

- FastAPI, bind `127.0.0.1` по умолчанию.
- `POST /api/jobs` — создать job; `GET /api/jobs` — список; `GET /api/jobs/{id}` — статус, этап, прогресс, клипы; `DELETE /api/jobs/{id}` — отмена (best-effort).
- `GET /api/jobs/{id}/events` — SSE с прогрессом; фронтенд имеет polling-fallback.
- `GET /files/...` — скачивание результатов с защитой от path traversal.
- Очередь: один worker-поток, максимум 3 job в очереди; статусы `queued/running/done/failed/cancelled`.
- UI: тёмная тема, русский язык, без сборщика; превью и ссылки на файлы.

### 5.8 CLI

- `run`, `trending`, `web`; все параметры дублируют веб-форму.
- Прогресс в stderr, итог — таблица клипов и путь.
- Коды выхода: 0 успех, 1 ошибка job, 2 ошибка аргументов.

### 5.9 Конфигурация

Defaults в `config.py`, переопределение через `config.yaml` и env:

- `AUTOCUT_OUTPUT` (по умолчанию `./output`),
- `AUTOCUT_PROXY`, `AUTOCUT_COOKIES`,
- `AUTOCUT_MODEL` (default `small`),
- `AUTOCUT_WORKDIR` (default `./work`).

### 5.10 Ошибки и логи

- Проверка ffmpeg/ffprobe при старте.
- Отдельные исключения: `DownloadError`, `TranscriptionError`, `RenderError`, `ConfigError`.
- Ошибка одного клипа не валит job: клип помечается failed, остальные сохраняются.
- Лог job пишется в `<result>/job.log` и в консоль.
- Понятные сообщения: нет места, битая ссылка, прокси недоступен, не скачалась модель, нет аудиодорожки.
- Отмена: флаг в job, проверяется между этапами и между клипами.

## 6. Зависимости

`yt-dlp`, `faster-whisper`, `numpy`, `fastapi`, `uvicorn`, `pydantic`, `PyYAML`; dev: `pytest`, `httpx`. Системные: `ffmpeg`/`ffprobe` (уже есть).

Python 3.14: wheel `ctranslate2` для cp314 проверен.

## 7. Тестирование

- Юнит: скоринг на синтетических массивах, NMS, привязка к фразам, группировка субтитров, slug/пути, парсинг опций.
- Интеграция: ffmpeg генерирует тестовый ролик (testsrc + sine), фиктивный транскрипт; полный цикл scoring → subtitles → render → storage без YouTube.
- API: TestClient с заглушкой pipeline; проверка статусов и path traversal.
- Ручной E2E: локальный файл; YouTube — после появления прокси (сейчас сеть блокирует youtube.com).
- Проверка результата: ffprobe (1080×1920, длительность, аудио), наличие ASS/SRT/metadata.

## 8. Производительность (ориентир)

16 CPU, 13 ГБ RAM: Whisper small ~0.5–1× реального времени; 30-минутное видео — анализ 15–30 мин, рендер 5 клипов 2–5 мин. Модель (~500 МБ) скачивается при первом запуске.

## 9. Риски

- YouTube блокируется с текущей машины — нужен прокси/VPN; без него проверяется только локальный файл.
- `trending` — нестабильный endpoint, реализуется best-effort.
- Авто-субтитры могут ошибаться на музыке/шуме; VAD снижает мусор.
- Кириллица в именах файлов допустима на Linux; для переносимости предусмотрен флаг `--ascii-slug`.
- Авторские права на исходное видео — ответственность пользователя.
